# 推广方案 · ai-optimize-master v0.2

> 原则（来自会审与 super-individual-os）：只说能复核的事实；不承诺提速/省钱百分比；
> 不把「分数」当成果。卖点只有一个——**查得清、审得过、回得去**。

## 一句话

**AI 工具越装越多，也能查清来源、审阅变更、恢复配置。**

- 对开发者：`scan` 告诉你同一份 skill 被复制到几个工具、哪些引用已断。
- 对运维：`plan` 先给方案和哈希，`apply` 才动手，`undo` 能回。
- 对所有人：MCP 面只读，远程调用方永远改不了你的机器。

## 面向谁（按优先级）

1. **同时用 3 个以上 AI CLI 的重度开发者**（Claude Code + Codex + Cursor + DSH）
2. **帮客户装机/巡检的人**（U-King 客户机、远程 Windows 维护）
3. 企业 IT / 平台团队（后置，需等权限模型与审计外发）

## 首发文案（可直接改）

**GitHub 描述（≤120 字符）**
> Read-only inventory of duplicate, broken and stale AI-tool skills; hash-bound plans, reversible archive.

**Show HN 标题**
> Show HN: A read-only auditor for the 392 duplicate skill files my AI tools accumulated

**掘金/公众号标题**
> 我的 AI 工具堆了 392 份 skill 副本、47 个断链：先查清，再清理

**正文骨架（四段）**
1. 现象：装得越多，同一份 skill 复制得越多；断链没人发现。
2. 为什么不能直接删：同名同内容 ≠ 没人用；同名不同内容更危险。
3. 做法：只读 scan → 带哈希的 plan → 逐项批准 → journal + undo。
4. 证据：16 条测试、真机数字、MCP 只读边界。

## 不承诺什么（写死在文案里）

- 不承诺「省 X% token」「快 N 秒」——没有对照组就不报。
- 不承诺「自动清理」——v0.2 必须人批准每一步。
- 不承诺「支持所有 AI 工具」——只在声明过的根上工作。
- 不把「AI 战斗力分数」当作治理成果——分数不是证据。
