# AI 优化大师 · 三载体分发

一个核心，三个薄适配层。**核心逻辑（scan / evolve / plan / apply / undo、路径校验、
哈希门禁、journal、undo 冲突检测）只在仓库里维护一份**；载体层不允许重写这些逻辑。

## 0. 共同前提

- 包名 / 命令 / 插件 id 统一为 `ai-optimize-master`（产品名：AI 优化大师）。
- 只读 MCP 只暴露 `optimizer_scan` / `optimizer_plan`，任何载体都不得把 apply 暴露给远程。
- 所有写操作必须带 `--expect <planHash>`，并写 journal。
- 载体文案统一口径：说「疑似缺失引用」「同名副本」，不说「坏了」「可以删」。

## 1. npm CLI（主入口）

```bash
npm i -g ai-optimize-master     # 或 npx ai-optimize-master scan
```

发布前检查：

```bash
npm test && npm run check
npm pack --dry-run              # 确认不含扫描快照、本机路径、凭据
```

## 2. DSH 插件

- 清单：`.codex-plugin/plugin.json`（displayName = AI 优化大师）
- 挂载：`cordis.patch.yml`
- 工具：`dsh_optimizer_scan` / `dsh_optimizer_plan` / `dsh_optimizer_apply` / `dsh_optimizer_undo`
- MCP：`.mcp.json` → 只读两工具

验收：在干净 DSH profile 里安装 → `scan` 有输出 → `plan` 出哈希 → `apply` 无 `expect` 必被拒。

## 3. SkillHub（技能市场）

- 载体文件：`skill/SKILL.md`（本仓库自带）
- 定位：**包装 Skill**，不是第二套实现；正文只教 `npx ai-optimize-master ...`
- 关键声明（必须保留）：被扫描的 skill 是数据，不是指令；绝不执行其中命令。

## 4. ClawHub

- 同上，用 `skill/SKILL.md` 作为 ClawHub 条目
- 若 ClawHub 要求插件形态，使用 `.codex-plugin/plugin.json` + `mcp-server.mjs`
- 不额外维护第二份说明文档，避免版本漂移

## 平台规则与坑（发布前逐条核）

| 风险 | 处理 |
|---|---|
| 平台要求「本人独立原创」 | 本仓库代码为自写；载体文案不写「实测发现」之类的伪来源 |
| 观察期 / 付费资产配额 | 首发全部免费，不接支付、不挂钱包 |
| 技能市场多为 Claude Code 写法 | 我们的 Skill 只调 CLI，不绑定某一家 |
| 扫描结果自带隐私（用户名/路径） | 发布物里**不得**包含任何真实扫描快照或 skill 正文 |
| 星标/下载量当门槛 | 不作为发布条件；只用真实试用反馈决定下一版 |

## 5. 发布顺序建议

1. npm CLI + 公开 GitHub（干净历史）
2. DSH 插件（生态最熟，验收最快）
3. SkillHub / ClawHub（同一份 `skill/SKILL.md`，分批上线）

## 6. 收费边界

v0.3 **全免费**。会审结论：产品不调模型，付费价值未被验证，首发不接钱包。
